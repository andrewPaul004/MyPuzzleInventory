## Decisions

### DL-1 — Working mode: Fast path
**Date:** 2026-05-20
**Decision:** Fast path chosen over Coaching path.
**Rationale:** Product brief and PRFAQ are exceptionally thorough — scope, personas, success metrics, V1 in/out list, competitive positioning, and monetization model already fully elaborated. Coaching path would re-cover ground already well-worked.
**Captured in:** Process decision; not a PRD section.

### DL-2 — Onboarding flow: Add-your-first-puzzle wizard
**Date:** 2026-05-20
**Decision:** Andrew confirmed preference for an "add your first puzzle" guided wizard pattern over a search-first flow.
**Rationale:** The "magic moment" (5+ puzzles logged in first 10 min) is the primary retention signal. The wizard actively drives the user toward that moment; a search-first flow is passive.
**Captured in:** PRD §4.4 (Onboarding Wizard), tagged `[ASSUMPTION]` for detailed flow design.

### DL-3 — Premium tier: Working hypothesis to be validated
**Date:** 2026-05-20
**Decision:** Draft a working hypothesis premium feature set based on brief context, tagged `[ASSUMPTION — validate before building]`. The PRFAQ explicitly noted the premium tier lacks user validation.
**Rationale:** PRD needs to document the revenue model assumption. The `[ASSUMPTION]` tag signals that the specific features require collector research before build.
**Captured in:** PRD §4.11 (Premium Tier) and §10 (Assumptions Index).

### DL-4 — Scope: Build for Megan first
**Date:** 2026-05-20
**Decision:** Primary persona is Megan (serious collector, 80+ puzzles, 1–3/month). Dan (competitive speed puzzler) is served incidentally by the same Completed status — no separate feature set needed.
**Rationale:** Confirmed from product brief. Megan represents the mass collector market; Dan is a smaller, higher-engagement audience already partially served by MySpeedPuzzling.
**Captured in:** PRD §2.

### DL-5 — Platform: Responsive web at launch; React Native on roadmap
**Date:** 2026-05-20
**Decision:** v1 is a responsive web app. React Native mobile app is explicitly confirmed for v2 roadmap.
**Rationale:** Confirmed by user during PRFAQ process.
**Captured in:** PRD §6 (MVP Scope) and §9 (Platform).

### DL-6 — Catalog strategy: In-house scrapers, not crowdsourced
**Date:** 2026-05-20
**Decision:** Catalog built and maintained via scheduled scrapers from brand/manufacturer sources. Not Wikipedia-style community contribution at launch.
**Rationale:** Consistent quality and coverage on anchor brands regardless of community activity. Community contribution (zero-results prompts) supplements but does not replace.
**Captured in:** PRD §4.1 (Puzzle Catalog).

### DL-7 — Data portability: CSV export always free
**Date:** 2026-05-20
**Decision:** CSV export of full collection and wishlist data is always free — never paywalled, never gated. Open data format published.
**Rationale:** Trust signal for platform-shutdown fear (documented in market research as real adoption barrier). Explicitly committed to in the PRFAQ.
**Captured in:** PRD §4.9 (Data Import/Export).

### DL-8 — Affiliate link sorting: By availability, not commission rate
**Date:** 2026-05-20
**Decision:** Buy links on puzzle pages sorted by availability/in-stock status, not by affiliate commission rate.
**Rationale:** User trust and transparency. Explicit commitment in PRFAQ Customer FAQ. Sorting by commission would undermine the trust relationship with collectors.
**Captured in:** PRD §4.7 (Affiliate Buy Links).

### DL-9 — Custom Puzzle records: Option A (in-app manual add)
**Date:** 2026-05-20
**Decision:** Users can create Custom Puzzle records for puzzles not in the catalog. Custom Puzzles are private to the creating User, not submitted for catalog review, and carry the same Status options as catalog Puzzles. Visually marked "User-added."
**Rationale:** PRFAQ FAQ Q6 makes an explicit customer-facing commitment: "For secondhand puzzles without a box, you can add them manually with whatever details you have." Omitting this would break a promise made to users. Option A (in-app manual add) chosen over Option B (out of scope) or Option C (partial/no image).
**Captured in:** PRD §3 Glossary (Custom Puzzle), §4.11 (FR-29, FR-30), §6.1 In Scope.

### DL-10 — Affiliate disclosure label required near Buy buttons
**Date:** 2026-05-20
**Decision:** A visible affiliate disclosure label is required adjacent to the Buy section on all Puzzle detail pages and Wishlist pages: "We may earn a referral fee on purchases made through these links."
**Rationale:** (1) Amazon Associates Operating Agreement requires clear and conspicuous disclosure. (2) PRFAQ FAQ Q4 is an explicit customer-facing transparency commitment. Both grounds independently mandate this.
**Captured in:** PRD §4.7, FR-20 (Retailer Link Display) consequences.
