MyPuzzleInventory — Design Directions

1 · The Gallery

Images do the work. Minimal chrome. Four-column grid fills the screen with box art — browsing feels like walking through a puzzle shop. Owned state appears as an amber glow pressing in from the card edges. Tap reveals title, brand, and piece count. Bottom navigation keeps thumbs in reach.

Maximum box art, minimum UI
Owned glow is unmistakable at a glance
Great for Megan's browsing sessions
Relies on catalog image quality
Metadata only on tap/hover

2 · The Library

Efficiency over imagery. Every puzzle row is scannable: thumbnail, title, brand, piece count, and status badge in one gesture. A persistent search bar and filter row make this a tool for power users who prefer text navigation. Think Letterboxd in list mode or a well-designed todo app.

Most catalog per scroll — information-dense
Status visible without interaction
Great for Dan (power user) and fast checking
Less emotionally resonant than image-first
Requires good metadata on every record

3 · The Shelf

Horizontal rows organized by brand, then by interest: "Your Collection," "From Your Wishlist," "New from Ravensburger." Users swipe through curated lanes rather than scrolling an infinite grid. Discovery is editorial and guided. Resonates with the Netflix/Spotify mental model many users already have.

Familiar mental model (Netflix/Spotify)
Brand organization matches how collectors think
Discovery-forward, not just catalog lookup
Less suited to "is this specific puzzle in my collection?"
Higher build complexity for row curation logic

4 · The Dashboard

Collection stats lead. Owned count, completed count, and wishlist size appear on a data hero the moment you open the app. Quick-add search below the stats. Activity feed beneath. This makes the collection itself the homepage — you see your identity as a collector first, then go looking. High shareability of stats.

Collection pride and identity front-and-center
Stats are highly shareable (social proof)
Reinforces "magic moment" by quantifying it
Empty state is weak until 5+ puzzles added
Catalog browsing is one tap away, not instant

5 · The Finder

The search bar IS the app. No hero, no rows, no stats — just a search box at the top of a clean screen. Results appear instantly below. This is the duplicate-check use case distilled to its atomic form: open → type → 9 seconds → done. Inspired by Spotlight, Raycast, and linear.app. Zero friction path to the core promise.

Fastest path to the core use case (duplicate check)
No learning curve — everyone knows search
Perfect for mobile mid-scroll Instagram check
Weak for discovery — doesn't help with "what next?"
Empty state before first search feels sparse

6 · The Collection

The collection grid is the primary screen. Tabs switch between Owned, Wanted, and Completed. Tiny status indicators in corners. Filter bar for brand/piece count. A "Share" button is always visible. This direction prioritizes Megan's identity as a collector — it's about the collection as an artifact, not search as a task.

Collection is the hero — matches collector identity
Share button always visible — drives organic growth
Satisfying to open daily and see the collection grow
Empty state is weakest of all six directions
Catalog discovery requires navigating away

Direction Comparison

1 · The Gallery

Image-dominant 4-column grid. Owned state as amber glow. Metadata only on tap. Bottom nav. Maximum visual richness per screen.

Best for: Megan browsing new arrivals; visual delight; collection pride
Weakest at: Quick text-based duplicate check; metadata density
Complexity: Medium
Depends on: Image quality (catalog must have images)

2 · The Library

Dense list with thumbnail + metadata per row. Persistent search bar. Buy links in wishlist mode. Most information per scroll.

Best for: Power users; fast ownership check; wishlist buying session
Weakest at: Emotional resonance; first impressions; social sharing
Complexity: Low
Depends on: Good metadata on all records

3 · The Shelf

Netflix-style horizontal rows by brand and interest. Editorial curation feel. Hero for featured puzzle. Profile share built-in.

Best for: Discovery; brand browsing; public profile / gift-giver view
Weakest at: The 9-second duplicate check; focused task completion
Complexity: High
Depends on: Curation logic; personalization data

4 · The Dashboard

Stats hero (Owned/Completed/Wanted counts) above the fold. Quick-add search. Activity feed. Collection becomes identity artifact.

Best for: Returning users; stat-sharing; collection pride; retention
Weakest at: New user empty state; first-time browsing
Complexity: Medium
Depends on: Engaging empty/sparse states

5 · The Finder

Search bar IS the homepage. Results appear below instantly. Zero chrome. Owned warning as prominent banner. Fastest path to core use case.

Best for: Mobile duplicate check; new users; focused intent
Weakest at: Discovery; browsing; emotional engagement; empty state
Complexity: Low
Depends on: Fast search (sub-200ms feel)

6 · The Collection

Collection grid is the homepage. Tabs for Owned / Wanted / Completed. Dense 3-col grid with corner status dots. Share always visible.

Best for: Collector identity; daily check-in; public profile quality
Weakest at: Empty state; catalog discovery; new user activation
Complexity: Low–Medium
Depends on: Compelling empty state design
The Core Question

All six directions use the same color system, typography, and component primitives. The difference is what appears first when Megan opens the app. Your answer to one question should decide the direction:

"When Megan opens this app without a specific puzzle in mind — just to browse — what do you want her to see first?"
Box art → Direction 1 or 6
Her stats → Direction 4
The catalog → Direction 2 or 5
